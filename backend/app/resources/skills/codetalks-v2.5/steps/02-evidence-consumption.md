# Step 02：输入材料消费和运行计划

## 目标

实际读取材料，并用 Markdown 向读者说明每份材料提供了什么证据。

## 必须输出

- `活文档/02-输入材料消费记录.md`
- `内部索引/输入材料索引.json`
- `内部索引/运行计划.json`
- `活文档/覆盖门禁/步骤02-覆盖门禁.md`

JSON 仅供脚本验证。完整材料说明必须在 Markdown 中。

## Markdown 结构

### 本阶段结论

说明材料是否足以支持后续分析，哪些证据最关键。

### 每份材料的消费说明

对每份代码、设计、日志、问题单、覆盖率文件说明：

- 实际读取了哪些范围；
- 提取了什么事实；
- 支持或反驳什么；
- 被哪些流程/Pass 使用；
- 未读取范围和影响。

### 覆盖率文件

提供 XLSX/XLS 时，Markdown 必须展示：

- 工作表；
- 表头和数据口径；
- 实际解析行数；
- 主要未覆盖文件/函数/行/分支；
- 与源码映射问题；
- 它将怎样驱动场景增殖。

不得只写“文件存在”。


## 问题单场景的 MR 消费

必须通过 `codehub-mcp-server` 实际读取 MR，并在 Markdown 中记录元数据、Commit、修改文件、Diff 范围、评审、流水线和未读取内容。只确认链接存在不算消费。


## 问题单场景的 MR 消费

## 目录限制

本步骤只写入 `活文档/` 和 `内部索引/`，不得写入 `正式输出/`。
