# Zero Public Egress Verification Record

## Intranet fail-closed regression (2026-07-24)

- Code change: `prepare_agent_sandbox()` now upgrades an intranet Agent launch from
  `auto` to required OS isolation. Explicit `sandbox_mode=off` and a missing platform
  isolation engine both fail before a subprocess starts.
- Call paths: AI-thread Agent bridge, workflow Agent Harness, readiness probes and
  external-agent discovery all propagate `intranet_require_os_sandbox=true`.
- Regression evidence: `backend/tests/test_agent_sandbox.py` and
  `backend/tests/test_agent_cli_bridge.py` cover auto-tool-missing rejection, explicit
  off rejection, and the AI-thread launch contract. Focused result: `3 passed`.

This closes the former path where a deployment certified an Agent model route but an
`auto` sandbox could silently degrade to an unsandboxed subprocess. It does not replace
the deployment firewall requirement for the narrowly approved model/MCP routes.

## Scope and remaining work

This validates the deny-all subprocess control only. It is not yet the full AC-SEC
evidence: CodeTalk must still enforce approved private endpoints for HTTP/SDK clients,
record `network_egress_blocked` events, capture traffic for the two SPDK workflows, and
 prove deployment-approved model/MCP hostnames remain usable under the production approved-purpose
 egress policy. Those hosts may use non-RFC1918 addressing; approval is by hostname or
explicit CIDR. An approved model API is allowed only through the adapter's declared API routes;
telemetry, tracing, updates, package registries and hosted MCP remain hard-denied.
