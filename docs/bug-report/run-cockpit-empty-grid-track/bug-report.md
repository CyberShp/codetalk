# 运行驾驶舱失败态挤压摘要

## 报告人

用户在桌面端查看失败 Attempt 时发现：失败详情几乎占满中间内容，摘要区域很薄，页面底部却留有大块空白。

## 复现步骤

1. 打开一个执行失败的任务 Attempt。
2. 在 `1440x900` 桌面视口查看摘要或事件区域。
3. 实际结果：运行工作区只有约 `189px` 高，底部存在未使用空间。
4. 期望结果：运行工作区保留主要阅读空间，失败详情和交付件使用下方结果区域。

## 根因分析

`.ct-v2-run-cockpit` 声明了页头、可选错误条、运行工作区、结果区四条 Grid 轨道，但子元素依赖自动放置。没有网络错误时，错误条不渲染，工作区和结果区向前错位，最后一条约占页面 34% 的轨道为空。该空轨道同时挤压运行工作区，产生“失败卡挡住摘要、底部仍有空白”的视觉结果。

## 修复方案

为页头、错误条、运行工作区和结果区显式指定 `grid-row`。可选错误条缺失时第二条自动轨道收缩为零，其余区域仍保持稳定位置。没有改变失败诊断、交付件或运行数据逻辑。

## 验证方式

真实 Playwright 失败态回归验证：

- 桌面运行工作区高度不小于 `300px`；
- 结果区紧接工作区且贴住驾驶舱底边；
- 失败详情完全位于结果区内；
- `390x844` 移动视口无水平溢出；
- 修复前测试以工作区实际高度 `189px` 失败，修复后通过。
